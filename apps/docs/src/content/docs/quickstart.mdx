title: Quickstart
description: Get up and running with bun-test-utils in 5 minutes.
---

In this quickstart, you will install `bun-test-utils`, initialize its preload, and compose your first Playwright-style fixture test.

## 1. Install & Initialize

```bash
bun add -d bun-test-utils
bunx test-utils init
```

The `init` command adds the preload plugin to `bunfig.toml`. It does not auto-load fixture files; create an extendable `test.ts` module for explicit composition.

## 2. Compose Fixtures

Edit `test.ts` and add project fixtures with `test.extend()`:

```ts
// test.ts
import { test as base } from "bun-test-utils";
export const test = base.extend({
  server: {
    scope: "session",
    setup: async (use) => {
      const server = await startTestServer();
      await use(server);
      await server.stop();
    },
  },
  user: {
    setup: async (use, { server }) => {
      const user = await server.insertUser({ name: "Ada" });
      await use(user);
    },
  },
});
```

## 3. Write a Test

Import the composed test from your local module:

```ts
// users.test.ts
import { expect } from "bun-test-utils";
import { test } from "./test";

test("finds created user", async ({ user }) => {
  expect(user.name).toBe("Ada");
});
```

Fixtures can depend on one another, have session, file, or test scope, and run teardown in reverse order.

## 4. Run Tests

```bash
bun test
```

`fixtures.ts` and `conftest.ts` are not automatically loaded. Fixtures are composed explicitly through the imported `test.extend()` chain. See [Scenarios & Fluent API](/bun-test-utils/guides/scenarios-and-fluent-api/) for shared state between fluent steps.


## Optional: Mock HTTP and switch web environments

Built-in mocks are fixtures too. `httpMock` handles fetch-based tests and
`browserHttpMock` installs the same handlers on Playwright routes. `webPage` runs
against happy-dom by default; set `BUN_TEST_UTILS_WEB_ENV=browser` when you want
a real Playwright page without changing the meaning of `browserPage`.

```ts
import { expect, test } from "bun-test-utils";

test("renders mocked data", async ({ webPage, httpMock }) => {
  httpMock.get("/api/user", () => Response.json({ name: "Ada" }));
  await webPage.setContent(`<main id="name"></main>`);

  const user = await fetch("https://app.test/api/user").then((r) => r.json());
  webPage.raw.document.querySelector("#name")!.textContent = user.name;

  expect(await webPage.textContent("#name")).toBe("Ada");
});
```

## Repository feature suites

In this monorepo, package feature files live at `packages/*/features/*.feature`
and are loaded by the root BDD entrypoint. Run the repo-wide BDD gate with:

```bash
bun run test:bdd
```
