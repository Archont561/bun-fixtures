description: Install bun-test-utils, compose a Playwright-style fixture, write a test, and run it with bun test.
---

This quickstart installs `@archont561/bun-test-utils`, composes a fixture with `test.extend()`, writes a test that uses it, and runs the suite with `bun test`.

## 1. Install and initialize

```bash
bun add -d @archont561/bun-test-utils
bunx test-utils init
```

`init` adds the package's preload to `bunfig.toml`. It asks for confirmation first in an interactive terminal, unless you pass `--yes`. The preload installs run-wide teardown hooks. It does not load any fixtures, so the next step defines them.

## 2. Compose a fixture

Create `test.ts` and extend the base `test` with your project's fixtures:

```ts
import { test as base } from "@archont561/bun-test-utils";

export const test = base.extend({
  server: {
    scope: "session",
    setup: async (use) => {
      const server = await startTestServer();
      await use(server);
      await server.stop(); // runs once, after the whole run
    },
  },

  user: {
    setup: async (use, { server }) => {
      const user = await server.insertUser({ name: "Ada" });
      await use(user); // built for each test, then discarded
    },
  },
});
```

Each fixture is a `setup` function. Destructuring a fixture from its second parameter declares a dependency on it. Everything after `await use(value)` is teardown, and it runs in reverse order even when the test fails.

## 3. Write a test

Import the composed `test` from your local module, and `expect` from the package:

```ts
import { expect } from "@archont561/bun-test-utils";
import { test } from "./test";

test("finds the created user", async ({ user }) => {
  expect(user.name).toBe("Ada");
});
```

Only the fixtures in the imported `test.extend()` chain are available to this file. A fixture is never picked up because of where a file sits in the tree.

## 4. Run the tests

```bash
bun test
```

## Optional: mock HTTP and choose a web backend

Built-in capabilities are fixtures on the root `test` context, so you request them the same way. `httpMock` handles fetch-based tests. `webPage` renders against happy-dom by default, and runs on a real Playwright page when you set `BUN_TEST_UTILS_WEB_ENV=browser`.

```ts
import { expect, test } from "@archont561/bun-test-utils";

test("renders the mocked user", async ({ webPage, httpMock }) => {
  httpMock.get("/api/user", () => Response.json({ name: "Ada" }));

  const user = await fetch("https://app.test/api/user").then((r) => r.json());
  await webPage.mount(`<h1 id="name">${user.name}</h1>`);

  expect(await webPage.textContent("#name")).toBe("Ada");
});
```

Install `happy-dom` for the default DOM backend, or `playwright` for the browser backend.
