## What it is

`bun-test-utils` is a general-purpose test extension for [`bun test`](https://bun.sh/docs/test/overview). It covers unit, integration, and end-to-end tests on the runner you already use, and it does not replace `bun:test`.

Its core is a fixture model in the style of Playwright Test. A fixture is a typed value built by a `setup` function. Tests ask for the fixtures they need by destructuring them, and the engine builds dependencies first, injects the values, and tears everything down in reverse order, even when a test fails.

```ts
// test.ts
import { test as base } from "@archont561/bun-test-utils";

export const test = base.extend({
  db: { scope: "file", setup: async (use) => { await use(await createDb()); } },
  user: { setup: async (use, { db }) => { await use(await db.insertUser("ada")); } },
});
```

```ts
// user.test.ts
import { expect } from "@archont561/bun-test-utils";
import { test } from "./test";

test("creates and verifies a user", async ({ db, user }) => {
  expect(await db.find(user.id)).toMatchObject({ name: "ada" });
});
```

`db` and `user` are built in dependency order, injected into the test, and torn down in LIFO order. Fixtures are available only through the imported `test.extend()` chain, so the test file is the complete list of what it depends on.

## What it covers

<div class="feature-grid">
  <div class="feature-card">
    <h3>🧩 Typed fixtures</h3>
    <p>Compose fixtures with <code>test.extend()</code>. Each fixture's type flows into the test that requests it, and a later definition overrides an earlier one.</p>
  </div>

  <div class="feature-card">
    <h3>⏱️ Scopes</h3>
    <p>Declare fixtures at <code>session</code>, <code>file</code>, or <code>test</code> scope. Long-lived resources are shared; short-lived ones are rebuilt per test.</p>
  </div>

  <div class="feature-card">
    <h3>🔄 LIFO teardown</h3>
    <p>Setup and teardown live in one function. Code after <code>await use(value)</code> runs in strict reverse order, including when the test fails.</p>
  </div>

  <div class="feature-card">
    <h3>🧪 BDD scenarios</h3>
    <p>Write fluent <code>given</code> / <code>when</code> / <code>then</code> tests on <code>test.scenario</code>. Scenario state and fixtures share one context.</p>
  </div>

  <div class="feature-card">
    <h3>🎲 Property-based testing</h3>
    <p>Run properties over generated values with <code>test.prop</code> and fast-check. Each generated sample gets fresh test-scoped fixtures.</p>
  </div>

  <div class="feature-card">
    <h3>📸 Snapshot testing</h3>
    <p>Compare values and files against stored snapshots with the <code>snapshot</code> fixture, with custom serializers and readable diffs.</p>
  </div>

  <div class="feature-card">
    <h3>📼 HTTP record/replay</h3>
    <p>Record a test's HTTP traffic once and replay it deterministically. Use <code>cassette</code> for recordings and <code>httpMock</code> for handlers.</p>
  </div>

  <div class="feature-card">
    <h3>🌐 DOM and browser</h3>
    <p>Test against happy-dom or a real headless Chromium through Playwright. The <code>webPage</code> fixture selects the backend with one environment variable.</p>
  </div>

  <div class="feature-card">
    <h3>📦 Standard fixtures</h3>
    <p><code>tmpdir</code>, <code>env</code>, <code>stdio</code>, <code>clock</code>, <code>seed</code>, and <code>networkGuard</code> give every test isolated, deterministic state.</p>
  </div>
</div>

## Stability

The fixture engine and the standard, DOM, snapshot, property-testing, and minimal cassette capabilities are stable and follow semantic versioning. Browser and BDD scenarios are experimental and may change in minor versions. Linux and macOS are supported; Windows support is planned. The [API reference](/bun-test-utils/reference/api/#stability-and-platforms) lists the compatibility boundaries.

* * *

## Quick setup

```bash
bun add -d @archont561/bun-test-utils
bunx test-utils init
```

`init` adds the package's preload to `bunfig.toml`. Then create a `test.ts` module, compose your fixtures there, and import it from your tests. The [quickstart](/bun-test-utils/quickstart/) walks through the whole flow.
